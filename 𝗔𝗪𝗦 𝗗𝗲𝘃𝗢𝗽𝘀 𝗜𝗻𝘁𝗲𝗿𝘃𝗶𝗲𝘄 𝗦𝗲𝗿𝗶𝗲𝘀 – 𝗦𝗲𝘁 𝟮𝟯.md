## 2. What is branching strategy in Git? Which Git branching strategy are you using?

### What is Git Branching Strategy?

A **Git branching strategy** is a defined way of creating, managing, and merging branches in Git.

It helps development and DevOps teams to:

- Manage multiple features and releases
- Isolate development work
- Perform code reviews
- Maintain stable production code
- Support CI/CD pipelines
- Reduce conflicts between developers

### Which Git Branching Strategy are you using?

In my projects, I have mainly used a **feature-based branching strategy with separate development, release, and production branches**.

The typical flow is:

```text
feature/* → develop → release/* → main
                         ↓
                    Production
Branches Used
main
 └── Production-ready code

develop
 └── Integration branch for development

feature/*
 └── Individual feature development

release/*
 └── Release preparation and testing

hotfix/*
 └── Critical production fixes
Example Workflow
Developers create a feature branch from develop.
git checkout develop
git pull origin develop

git checkout -b feature/login
Developers implement the changes and push the feature branch.
git add .
git commit -m "Added login feature"
git push origin feature/login
A Pull Request is created from:
feature/login → develop
After code review, testing, and CI checks, the feature is merged into develop.
When the release is ready, we create a release branch.
git checkout develop
git checkout -b release/v1.2.0
After UAT and final validation, the release is merged into main.
release/v1.2.0 → main
The main branch represents the production-ready code and triggers the production CI/CD pipeline.
Hotfix Flow

For critical production issues, we create a hotfix branch from main.

main → hotfix/* → main
              ↓
           develop

Example:

git checkout main
git checkout -b hotfix/payment-fix

After fixing and testing:

hotfix/payment-fix → main
hotfix/payment-fix → develop
Interview Answer — Short Version

"Git branching strategy defines how we create and manage branches throughout the software development lifecycle. In my projects, I have used a feature-based branching strategy with feature, develop, release, main, and hotfix branches. Developers work on feature branches and create Pull Requests to merge them into develop. After testing and validation, we create a release branch and eventually merge it into the main branch for production deployment. For critical production issues, we use hotfix branches from main. This approach provides better code isolation, code review, release management, and supports our CI/CD process."
